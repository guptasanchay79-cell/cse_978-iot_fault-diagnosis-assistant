Physical Failure Modes Classified

  • HDF (Heat Dissipation Failure): ΔT < 8.6 K and Speed < 1380 rpm
  • TWF (Tool Wear Failure): Cumulative abrasive wear exceeds 200 min
  • PWF (Power Failure): Motor torque × speed out of safe power band
  • OSF (Overstrain Failure): Tool wear × torque product limits breached
  • RNF (Random Failure): Uncorrelated hardware anomalies (0.1% chance)

Physical Domain Feature Engineering Formulas

Raw sensor readings are transformed using thermodynamics and mechanical rotation equations:

# 1. Thermal Gradient (Thermodynamic heat dissipation) temp_diff_k = df['Process temperature [K]'] - df['Air temperature [K]'] # 2. Mechanical Rotational Power (Watts) rotational_power_w = df['Torque [Nm]'] * (df['Rotational speed [rpm]'] * (2 * pi / 60)) # 3. Mechanical Overstrain Risk (min * Nm) overstrain_risk = df['Tool wear [min]'] * df['Torque [Nm]']

Centrifugal Slurry Pump Sensor Integration

In this P_311 SCADA pipeline, these failure dynamics directly govern pump telemetry thresholds:

  • Motor Temperature (RTD): Nominal: 45–65°C | Warning: ≥70°C | Critical Overheating: ≥75°C
  • Radial Vibration RMS: ISO 10816 Zone A/B: <2.8 mm/s | Zone C Alert: ≥2.8 mm/s | Zone D Danger: ≥4.5 mm/s
  • Pump Discharge Pressure: Nominal: 4.5–5.5 bar | Low Hydraulic Pressure (Cavitation/Leak): <3.0 bar

PostgreSQL Persistence Architecture

Database Name: iot_fault_diagnosis on 127.0.0.1:5432 (Windows Native Service).

Persistence Decoupling: Asynchronous batch queue buffers 1 Hz telemetry without blocking real-time MQTT streaming. Circuit-breaker health check fails gracefully if PostgreSQL is restarting.

Table: sensor_readings

Stores raw 1 Hz continuous sensor streams & fault predictions:

  • Columns: id, timestamp, device_id, temperature, vibration, pressure, fault_status, mode, created_at
  • Live Rows: -- rows
  • Indexes: timestamp DESC, (device_id, timestamp DESC), fault_status
  • Pruning: Hourly rolling retention cleanup (7-day window)

Table: fault_incidents

Stores full RAG grounding provenance and LLM reports:

  • Columns: id, timestamp, device_id, fault_category, symptoms, retrieved_sources, diagnosis_text, likely_fault, why, recommended_checks, runtime, latency_seconds
  • Live Incidents: 15+ recorded
  • Constraint: Unique on (device_id, timestamp) for idempotency
